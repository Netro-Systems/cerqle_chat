# Cerqle Flutter SDK API Contract

This document summarizes the public Flutter API and the visitor-session behavior
implemented by this package.

## Runtime initialization

Initialize once before `runApp` when the application needs push handling,
API-provided branding, startup visitor registration, or pre-open unread state:

```dart
final navigatorKey = GlobalKey<NavigatorState>();
const config = CerqleConfig(widgetKey: 'YOUR_WIDGET_KEY');

await CerqleChat.initialize(
  config: config,
  navigatorKey: navigatorKey,
  onNotificationTapped: (payload) {},
);
```

Initialization registers the visitor by default. Set
`registerUserOnStartup: false` to defer the session until chat is explicitly
opened. Deferred launchers use local fallback branding and cannot receive
realtime unread updates before that first open.

## Presentation entry points

Supported surfaces are `CerqleChatScreen`, `CerqleChatLauncher`,
`CerqleChatView`, `CerqleChat.open(...)`, and a headless
`CerqleChatController`.

```dart
await CerqleChat.open(
  context,
  config: config,
  presentation: CerqlePresentation.bottomSheet,
);
```

`CerqleChat.badge(...)` wraps an application-owned button with realtime unread
state. `CerqleChatLauncher(showBadge: true)` provides the same capability on
the built-in FAB. Opening chat through any entry point marks messages read and
clears all registered badges in the same configuration scope.

`CerqleChat.resetSession(config: config)` deletes stored credentials and resets
any facade-owned active controller.

## Headless controller

The controller exposes immutable snapshots through `state`, broadcast updates
through `states`, and lifecycle events through `events`. Its primary methods are:

```dart
Future<void> initialize();
Future<void> refresh();
Future<CerqleMessage> sendText(String text);
Future<CerqleMessage> sendImage(CerqleUpload upload, {String? caption});
Future<CerqleMessage> sendAudio(CerqleUpload upload, {String? caption});
Future<CerqleMessage> sendFile(CerqleUpload upload, {String? caption});
Future<Uint8List> loadAttachmentBytes(CerqleAttachment attachment);
Future<CerqleMessage> retryMessage(String localId);
Future<void> removeMessage(String localId);
Future<void> setTyping(bool isTyping);
Future<void> requestHumanAgent();
Future<void> submitPreChat(CerqlePreChatData data);
Future<void> markRead();
Future<void> updateUser(CerqleUser? user);
Future<void> resetSession();
Future<void> dispose();
```

`CerqleChatState.unreadCount` and `hasUnreadMessages` support custom badges.
Headless conversation UIs must call `markRead()` when messages become visible.

Passing `null` to `updateUser` is the host-application logout operation. It
stops realtime streaming, sends typing `false` on a best-effort basis, unlinks
OneSignal device tags, deletes the identity-scoped visitor credentials, clears
in-memory messages, and returns the controller to `idle`. A later `initialize()`
creates a fresh anonymous session.

## Identity and session storage

`CerqleUser` maps directly to the session payload:

| Dart | JSON |
|---|---|
| `name` | `name` |
| `email` | `email` |
| `avatarUrl` | `avatar` |
| `externalId` | `external_id` |
| `signature` | `user_hash` |
| `customFields` | `custom_fields` |

Signatures are HMAC-SHA256 values generated by the integrating company's
server with the widget identity secret. The secret must never enter a Flutter
application. Arbitrary application metadata belongs in `customFields`.

The encrypted visitor token is the authority for one conversation. The default
store keeps the matching visitor ID and token together in secure storage under
a base-URL, widget-key, and identity-scoped namespace.

## Message presentation

The prebuilt UI supports text, images, audio, and file attachments. HTTP(S) and
`www.` URLs inside sent or received text are blue, underlined, selectable, and
opened through the platform's external browser.

## Push notifications and realtime streaming

`CerqleChat.initialize(...)` owns OneSignal setup. The SDK retrieves the push
subscription ID and attaches it to session requests when push is enabled.
Lifecycle-aware Pusher channels
(`private-widget-conversation.{conversationId}`) deliver live messages, typing,
handoff changes, and unread state. Foreground resume and explicit pull-to-refresh
perform bounded catch-up requests; no periodic polling scheduler is used.
